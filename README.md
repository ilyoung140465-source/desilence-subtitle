# TTS 무음 제거 + 자막 싱크 도구

타입캐스트 TTS 음성의 무음 구간을 자동으로 찾아 잘라내고, 그만큼 SRT 자막 타임코드를
다시 계산해서 내보냅니다. 자막은 단어를 끊지 않고 기본 10자 내외로 균등 분할합니다.

두 가지 방식이 있습니다.

| | Python CLI | 웹 (브라우저) |
|---|---|---|
| 파일 | `desilence.py` | `web/index.html` |
| 설치 | Python + ffmpeg 필요 | 없음 (더블클릭) |
| **자막 싱크 실측 보정** | **O** | X |
| 여러 파일 일괄 처리 | O | X (1개씩) |
| MP3 내보내기 | O | X (WAV만) |
| 파형 보고 값 조절 | X | O |

## 다른 PC 로 옮기기

이 폴더를 통째로 복사한 뒤, 그 PC에서 **`install.bat` 을 더블클릭**하면 끝입니다.
Python·ffmpeg·필요 패키지·GPU 라이브러리를 알아서 확인하고 없는 것만 설치합니다.

복사해야 할 파일:

```
desilence.py      무음 제거 + 자막 처리
aligner.py        Whisper 싱크 보정
to_capcut.py         캡컷 프로젝트 생성
capcut_export.py     캡컷 내보내기 (이름·비율 물어봄)
capcut_skeleton.json 캡컷 포맷 골격 (새 PC 용, 개인정보 없음)
setup.py          설치 스크립트 (install.bat 이 호출)
install.bat       ← 새 PC 에서 이것부터 더블클릭
run.bat           ← 평소 사용: 오디오를 이 위로 끌어다 놓기
capcut.bat        ← 캡컷으로 내보내기
web/index.html    브라우저 버전 (선택)
```

Python 이 없으면 install.bat 이 안내를 띄웁니다. python.org 에서 받아 설치할 때
**"Add python.exe to PATH" 체크를 꼭** 하세요. ffmpeg 는 winget 으로 자동 설치를 시도합니다.

### 새 PC 에 GPU 가 없다면

싱크 보정이 10배 이상 느려집니다 (60초 영상에 5~9분). 이럴 땐:

```bash
python desilence.py "파일.mp3" --model small    # 조금 빠르게
python desilence.py "파일.mp3" --no-align       # 싱크 보정 끄기 (즉시)
```

무음 제거와 자막 분할 자체는 GPU 없이도 순식간에 끝납니다.

## 1. Python CLI

### 준비
```bash
pip install numpy faster-whisper
```
ffmpeg / ffprobe 가 PATH 에 있어야 합니다. (이미 설치되어 있음)

GPU 로 싱크 보정을 돌리려면 (없으면 CPU 로 동작하지만 10배 이상 느림):
```bash
pip install nvidia-cublas-cu12 nvidia-cudnn-cu12
```

### 기본 사용
오디오와 같은 폴더에 같은 이름의 `.srt` 가 있으면 자동으로 찾아서 함께 처리합니다.

```bash
python desilence.py "C:\tts\20260820_나레이션.mp3"
```

결과: `20260820_나레이션_clean.mp3` + `20260820_나레이션_clean.srt`

### 폴더 통째로 일괄 처리
```bash
python desilence.py "C:\tts" -o "C:\tts\clean"
```

### 자르기 전에 결과만 확인
```bash
python desilence.py "C:\tts" -n -v
```

### 자주 쓰는 옵션

| 옵션 | 기본값 | 설명 |
|---|---|---|
| `-t, --threshold` | `-30` | 무음 임계값(dBFS). 낮출수록 덜 자름 |
| `--auto-threshold` | – | 임계값을 파일마다 자동 계산 (`-t` 무시) |
| `-m, --min-silence` | `0.10` | 이 길이(초) 이상인 무음만 자름 |
| `-k, --keep-silence` | `0.05` | 자를 때 앞뒤로 남길 여백(초). 무음이 이 값의 2배로 줄어듦 |
| `-c, --max-chars` | `10` | 자막 한 줄 최대 글자 수 |
| `--format` | `mp3` | `mp3` 또는 `wav` |
| `-o, --outdir` | 원본 폴더 | 출력 폴더 |
| `--min-cue` | `0.45` | 자막 최소 노출 시간(초) |
| `--offset` | `0` | 자막 전체를 밀기(ms). 음수면 자막이 먼저 뜸 |
| `--no-tighten` | – | 자막 구간을 실제 발화 구간으로 좁히지 않음 |
| `--raw-text` | – | 대본 표기(`-` 쉼 표시 등)를 그대로 둠 |
| `--keep-gaps` | – | 자막 사이 빈틈을 그대로 둠 (기본은 빈틈 없이 이어 붙임) |
| `--no-align` | – | Whisper 싱크 보정을 끄고 글자 수 비례 추정만 사용 |
| `--model` | `medium` | Whisper 모델. `large-v3` 는 더 정확하지만 느림 |
| `--trust-shift` | `0.25` | 비례 추정과 이만큼(초) 이상 어긋날 때만 Whisper 결과 채택 |
| `--whisper-bias` | `-30` | 자막 전체를 이만큼(ms) 밀기. 실측 최적값 |
| `--anchor` | – | 문장 시작점 고정 (실측상 정확도가 떨어져 기본은 끔) |
| `--no-snap` | – | 자막 경계를 에너지 최저점으로 당기지 않음 |
| `-n, --dry-run` | – | 분석만 하고 파일은 쓰지 않음 |
| `--save-map` | – | 잘라낸 구간 목록을 json 으로 저장 |

### 기본값에 대해

기본값 `-30 / 0.1s / 0.05s` 는 **숏폼 광고용 타이트한 편집**을 노린 값입니다.
단어 사이 짧은 틈까지 잘라내 속도감을 만듭니다.

말이 급하게 들리면 다음 순서로 완화하세요.

```bash
python desilence.py "파일.mp3" -k 0.10           # 여백 늘리기 (가장 효과적)
python desilence.py "파일.mp3" -m 0.25           # 짧은 틈은 건드리지 않기
python desilence.py "파일.mp3" --auto-threshold  # 임계값 자동 (가장 보수적)
```

37초 한국어 TTS 샘플 기준 비교:

| 설정 | 잘라낸 구간 | 결과 길이 |
|---|---|---|
| 기본값 (`-30 / 0.1 / 0.05`) | 41곳 | 20.98초 (43.8% 단축) |
| 보수적 (`auto / 0.35 / 0.12`) | 8곳 | 23.41초 (37.3% 단축) |

## 2. 웹 버전 (앱)

**`무음제거 열기.bat` 를 더블클릭**하면 엔진과 편집 화면이 함께 켜집니다.
검은 창은 작업하는 동안 켜 두세요 — 그게 엔진입니다. 닫으면 종료됩니다.

각 설정은 슬라이더로 대충 맞추거나 **오른쪽 숫자칸에 직접 입력**할 수 있습니다
(Enter 로 적용, 범위를 벗어나면 자동으로 제한됩니다).

**인식한 그대로 (대본 무시)** 를 켜면 대본을 쓰지 않고 Whisper 가 들은 말로 자막을 만듭니다.
싱크는 구조적으로 완벽하지만, 인식 오류가 그대로 자막이 됩니다
(예: `그래애~` → `그래`). 대본의 표기를 살리려면 꺼 두세요.

설정 슬라이더는 창을 열 때마다 기본값(-30dB / 0.10s / 0.05s / 10자)으로 초기화됩니다.
브라우저가 이전 값을 복원해 다른 결과가 나오는 일을 막기 위해서입니다.
지금 적용된 설정은 통계 줄 아래와 엔진 결과 메시지에 항상 표시됩니다.

### 참고: 브라우저로만 열었을 때

`web/index.html` 을 더블클릭하면 브라우저에서 바로 열립니다.
설치가 전혀 필요 없는 대신 **싱크 보정 기능은 없습니다** (브라우저가 GPU 를 못 씁니다).
서버·설치·인터넷 연결이 필요 없고, 파일이 밖으로 나가지 않습니다.

**`app.py` 로 실행하면** 파일을 넣는 즉시 파이썬 엔진이 전체 처리를 맡습니다
(무음 제거 → 자막 구간 좁히기 → 음성 인식 기반 분할 → 문장 시작점 고정).
브라우저 단독으로 열면 엔진 기능 없이 글자 수 기준으로만 동작합니다.

1. 오디오와 SRT를 드래그 (두 개 동시에 가능)
2. 슬라이더로 무음 제거 정도를 맞춤 — 파형의 빨간 선이 잘라낸 지점
3. **자막 블록을 직접 편집** (캡컷과 비슷한 방식)
   - 블록 클릭 → 선택, 아래에서 내용 수정
   - 블록 좌우 끝을 끌어 길이 조절 (붙어 있으면 옆 자막도 함께 움직임)
   - 가운데를 끌어 이동, 파형 클릭으로 재생 위치 이동
   - 앞뒤 자막의 영역을 침범할 수 없습니다. 붙어 있던 자막은 함께 밀리고,
     떨어져 있던 자막의 경계는 벽이 됩니다
   - 시간이 겹치는 자막은 **아래 줄에 따로 표시**됩니다 (캡컷과 같은 방식)
   - **자막 하나씩 검사**: <kbd>←</kbd><kbd>→</kbd> 로 옮기면 그 자막 구간만 재생됩니다.
     들리는 말이 자막 내용과 같으면 싱크가 맞는 것 — 재생 바를 눈으로 좇을 필요가 없어
     **원격 접속에서도 확실합니다**
   - **소리 지연** 슬라이더: 원격 접속처럼 소리가 늦게 들릴 때 재생 바만 늦춥니다.
     자막 파일에는 영향이 없습니다
   - **자막 밀기** 슬라이더로 전체 싱크를 조정 (±400ms)
   - <kbd>[</kbd> <kbd>]</kbd> 로 선택한 자막만 10ms씩 미세 조정
   - <kbd>Space</kbd> 재생 · <kbd>S</kbd> 나누기 · <kbd>M</kbd> 합치기 · <kbd>Del</kbd> 삭제 ·
     <kbd>←</kbd><kbd>→</kbd> 이전/다음 · <kbd>Ctrl</kbd>+<kbd>Z</kbd> 되돌리기 ·
     <kbd>Ctrl</kbd>+<kbd>Y</kbd> 다시 실행
4. **WAV 다운로드** + **SRT 다운로드**

### 완성된 자막 검토 · 두 버전 비교

이미 정리한 결과물을 검토할 때는 체크박스 두 개를 켜세요.

- **무음 제거 안 함** — 이미 정리된 오디오를 다시 자르지 않음
- **자막 그대로** — 완성된 SRT 를 다시 쪼개지 않고 그대로 표시

여기에 **비교용 SRT 불러오기** 로 다른 SRT 를 얹으면 아래 줄(파란색)에 나란히 표시됩니다.
같은 파형 위에서 두 버전의 자막 경계를 눈으로 비교할 수 있고,
어느 쪽 블록이든 클릭하면 그 구간만 재생됩니다.

이미 정리한 `_clean` 파일과 SRT를 넣고 **"무음 제거 안 함"** 만 켜면
자막을 다시 나눠 다듬는 용도로 쓸 수 있습니다. Python 으로 처리한 결과를 여기서 검수하는 흐름이 편합니다.

브라우저에서는 MP3 인코더를 쓸 수 없어 WAV로 저장됩니다.
캡컷은 WAV를 그대로 받으므로 작업에는 문제가 없습니다.
MP3가 꼭 필요하면 Python CLI를 쓰세요.

## 동작 방식

1. **무음 감지** — 10ms 프레임마다 RMS를 dBFS로 계산하고, 임계값 아래 프레임이
   `min-silence` 이상 이어지는 구간을 무음으로 판정합니다.
   임계값은 노이즈 플로어(하위 10%)와 발화 레벨(상위 90%)로부터 자동 산출합니다.
2. **잘라내기** — 무음 구간의 앞뒤 `keep-silence` 만 남기고 제거한 뒤,
   이음새마다 4ms 페이드를 넣어 클릭음을 막습니다.
3. **시간 매핑** — 남긴 구간들의 누적 길이로 `원본 시각 → 편집 후 시각` 함수를 만듭니다.
   삭제된 구간 안의 시각은 이음새로 스냅됩니다.
4. **자막 재계산** — 각 자막의 시작/끝을 매핑하고, 텍스트를 단어 단위로 나눕니다.
   나눌 자리는 세 가지를 함께 따져 정합니다(DP 로 전체 최적을 찾습니다).

   | 기준 | 내용 |
   |---|---|
   | 길이 | `max-chars`(기본 10자) 에 가깝게. 조금 넘는 건 허용(최대 14자) |
   | 실제 쉼 | 단어 사이가 실제로 벌어진 자리에서 끊으면 가산점 |
   | 한국어 어법 | 뜻 덩어리를 깨지 않는 자리 우선 |

   어법 규칙은 이렇습니다.

   - `게 / 것 / 수 / 줄 / 때` 처럼 앞말에 기대는 말로 **줄을 시작하지 않음**
     (`기다렸던` + `게 이거예요…` ✗ → `기다렸던 게` + `이거예요…` ✓)
   - `안 / 못 / 한 / 그` 처럼 뒷말에 붙는 말로 **줄을 끝내지 않음**
     (`관련한 거 안` + `해본 게` ✗ → `이거 관련한 거` + `안 해본 게` ✓)
   - 한 글자만 남기고 끊지 않음 (`그거니 남` + `얘기인…` ✗)
   - 문장부호나 어미(`요 / 다 / 고 / 서`)로 끝나는 자리는 좋은 자리
   - 원본 문장(SRT 자막) 경계는 절대 넘지 않음
   각 조각의 시간은 공백 제외 글자 수에 비례해 배분한 뒤,
   ±0.2초 안에서 에너지가 가장 낮은 지점(= 말 사이 틈)으로 경계를 당깁니다.
5. **싱크 실측 보정** — 정리된 오디오를 Whisper 로 인식해 단어별 실제 발화 시각을
   얻고, 대본 글자를 그 타이밍에 정렬합니다(forced alignment).
   비례 추정과 `trust-shift` 이상 어긋난 자막만 교체합니다 — 비례 추정은 국소적으로
   정확하고(중앙값 ~27ms) Whisper 는 자체 오차가 ~100ms 있어서, 큰 드리프트만
   Whisper 로 잡는 편이 둘 중 하나만 쓰는 것보다 정확합니다.
   인식 일치율이 45% 미만이면 보정을 포기하고 원래 타이밍을 지킵니다.
6. **자막 구간 좁히기** — 타입캐스트 SRT 는 문장 앞뒤 무음까지 자막 구간에 포함합니다
   (실측: 앞 178ms, 뒤 282ms). 그대로 두면 늘어난 자를 쓰는 셈이라 문장 뒤로 갈수록
   밀립니다. 그래서 각 자막을 실제 발화 구간으로 좁힌 뒤 처리합니다.
7. **전체 -30ms 보정** — 자막은 약간 먼저 뜨는 편이 낫습니다. 늦게 뜨면 단어 첫음절이
   잘려 읽기 나쁩니다. 오프셋을 ±120ms 훑어 잰 최적값입니다.

### 하지 않는 것: 문장 시작점 고정

문장 첫 단어를 파형에서 잡은 발화 시작에 맞추는 기능을 넣었다가 **뺐습니다.**
좋아 보였지만 실측하니 오히려 나빴습니다 (구간별 인식 대조: 앵커 0.877 vs 없음 0.918,
-30/-40/-50dB 어느 임계값에서도 마찬가지). 파형에서 잡는 발화 시작이 실제보다
늦기 때문입니다. `--anchor` 로 켤 수는 있지만 권하지 않습니다.
8. **빈틈 메우기** — 기본적으로 각 자막은 다음 자막이 시작할 때까지 유지되어,
   타임라인에 빈 구간 없이 0초부터 끝까지 이어집니다. `--keep-gaps` 로 끌 수 있습니다.

### 싱크 정확도 (34.5초 한국어 TTS, 단어 위치를 정확히 아는 합성 샘플 기준)

| 방식 | 평균 오차 | 최대 오차 | 100ms 이내 |
|---|---|---|---|
| 보정 없음 (비례 추정만) | 59ms | 413ms | 88% |
| Whisper 결과 전면 채택 | 62ms | 178ms | 82% |

## 캡컷으로 내보내기 (자동)

**`capcut.bat` 위로 오디오와 SRT 를 끌어다 놓으면** 프로젝트 이름과 화면 비율을
물어본 뒤 캡컷 프로젝트를 통째로 만들어 줍니다. 캡컷을 켜면 목록에 바로 나타납니다.

```
캡컷 프로젝트로 내보내기
  오디오 : tts_clean.wav
  자막   : tts_clean.srt
프로젝트 이름 [260823_tts_clean]: 0824_광고A
  화면 비율: 1) 9:16 / 2) 1:1 / 3) 4:5 / 4) 16:9
  번호 선택 [1]: 3
■ 캡컷 프로젝트 생성
  이름   : 0824_광고A
  화면   : 1080x1350 (4:5) @ 30fps
  자막   : 18개
```

명령줄로도 됩니다.

```bash
python to_capcut.py "소리.wav" "자막.srt" --name "0824_광고A" --ratio 9:16
```

| 옵션 | 기본값 | 설명 |
|---|---|---|
| `-n, --name` | 오디오 파일명 | 캡컷에 표시될 프로젝트 이름 |
| `-r, --ratio` | `9:16` | `9:16` / `1:1` / `4:5` / `16:9` |
| `--fps` | `30` | 프레임레이트 |
| `--force` | – | 캡컷이 켜져 있어도 진행 |

**주의**

- **캡컷을 끄고** 실행하세요 (켜져 있으면 막습니다)
- 기존 프로젝트는 읽기만 하고 **새 폴더만** 만듭니다. 마음에 안 들면 그 폴더만 지우면 됩니다
- 오디오 파일을 절대경로로 참조하므로 **원본을 옮기거나 지우면** 캡컷이 파일을 못 찾습니다
- 캡컷 내부 포맷은 공개 규격이 아닙니다. 버전이 크게 오르면 안 맞을 수 있습니다
  (현재 9.3.0 확인)

### 다른 PC 에서도 그대로 됩니다

프로젝트 폴더 위치(`%LOCALAPPDATA%\CapCut\...`)를 실행하는 PC 기준으로 알아서 찾고,
폰트 경로도 그 PC 에 설치된 캡컷에서 다시 찾습니다. 사용자 이름이나 캡컷 버전이
달라도 상관없습니다.

포맷 구성 정보는 이 순서로 확보합니다.

1. 그 PC 의 기존 캡컷 프로젝트 중 오디오+자막이 있는 것 (최근 순으로 탐색)
2. 없으면 함께 배포되는 `capcut_skeleton.json`

그래서 **캡컷을 막 설치해 프로젝트가 하나도 없는 PC 에서도 동작합니다.**
골격 파일에는 기기 식별자·사용자 경로·원본 자막이 들어 있지 않습니다.

캡컷이 크게 업데이트되어 포맷이 바뀌면, 캡컷에서 프로젝트를 하나 저장한 뒤
아래를 실행해 골격을 새로 뜨면 됩니다.

```bash
python to_capcut.py --make-skeleton
```

## 캡컷에 직접 넣기 (수동)

1. 결과 `_clean.mp3` (또는 `.wav`) 를 타임라인 **0초**에 올립니다.
2. 자막 → 로컬 자막 가져오기 → `_clean.srt`.

자막은 오디오 0초 기준이므로, 오디오를 0이 아닌 위치에 놓으면 자막 트랙도
같은 값만큼 밀어야 합니다.

### 호환성 (검증 완료)

| 항목 | 출력 | 비고 |
|---|---|---|
| 자막 형식 | 표준 SRT | 번호 1부터 연속, `HH:MM:SS,mmm --> ...` |
| 인코딩 | UTF-8 + BOM | 윈도우에서 한글 안 깨짐 |
| 오디오 | MP3 44.1kHz 192kbps / WAV | 캡컷이 그대로 받음 |
| 겹치는 자막 | 허용 | 캡컷이 자막 트랙을 나눠서 표시 |

SRT 를 저장할 때마다 자동으로 점검하고, 문제가 있으면 `⚠` 로 알려줍니다
(너무 짧은 자막, 시간 역전, 빈 자막, 오디오 길이 초과, 겹침).
